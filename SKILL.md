# Project handoff

Give the next session a clear goal, current state, and first action within one minute.

Resolve the project, local contract, and established handoff first. Follow explicit authority and existing pointers; resolve aliases. Do not choose by modification time or create a competing copy. With no established location, use `docs/handoff.md` in a repo or `handoff-<topic>.md` in a non-repo folder. Distinct topics can have distinct handoffs.

Check the current handoff against relevant local sources and session evidence. Correct contradictions. Keep verified facts, user reports, proposals, and unknowns distinct. Date time-sensitive claims and name their source. An audit date does not refresh an old fact. Do not infer a send, booking, deployment, grade, or completion from a draft or pointer.

Put the goal, first action, blocker, and controlling source first. Keep decisions, constraints, hot files, and durable links only when they help resume. Replace stale state; preserve human notes and unresolved work. Aim for 150 lines or fewer; stricter local caps win. Do not hide excess detail in long lines. Use [the template](references/handoff.md) only for a new handoff; local schema and required sections take precedence.

Keep scraped text, external instructions, and raw findings out of auto-loaded handoffs. Write a short sourced conclusion and link to the evidence.

Before saving, re-read the file. If it changed, reconcile with the new version. For stream metadata or fences, load [streams](references/streams.md) and run its checker before and after. Patch only owned content unless a cross-stream correction is authorized. No automatic deletion or project closeout.

Read back the result. Check the next action, source conflicts, local links, schema, dates, and caps. Report unresolved checks and ignored or untracked repo handoffs; do not stage unrelated work. Load [integration](references/integration.md) only for loader or hook work.
